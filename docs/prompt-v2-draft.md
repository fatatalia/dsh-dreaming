# dsh-dreaming v2 — 梦境 Prompt 草案（待审）

> 状态：草案，未落地。目标：让梦境日记从"有情绪的一天回顾"变成"真正的梦"。
> 对比依据：OpenClaw `dreaming-narrative-*.js` 的 NARRATIVE_SYSTEM_PROMPT + 咱们 v1 的 `dreamPrompt()`。

---

## 0. 核心改动（和 v1 的差异）

| # | 改动 | 理由 |
|---|---|---|
| 1 | **一把梭 → 两个 prompt**：`narrative`（写梦）+ `insight`（提炼洞察） | v1 让同一个 agent 边取材边写梦边提炼边输出 JSON，模型把"讲清楚今天"当优先级，梦成了附属品 |
| 2 | **素材预拉取注入，不再让 agent 自己 curl** | v1 让 agent 用工具去 Hindsight recall，一半精力花在找素材；v2 由引擎在创建会话前拉好碎片，注入给 agent，只专注写作 |
| 3 | **注入碎片而非整块记忆**（每条 ≤280 字符 + 来源标签 + 编号） | 不完整的碎片诱发模型"补全、拼接、扭曲"——这正是梦的工作方式；整块记忆只会被照着讲 |
| 4 | **照抄 OpenClaw 三条反直觉铁律**：禁 meta-commentary / 禁技术自指 / 强制短 | 逼模型"进入梦本身"而不是"描述梦"；洗掉 AI 身份包袱；用长度制造梦的凝缩 |
| 5 | **法塔人格移到洞察层与呈现层**，梦境正文保持"无我" | v1 把"傲娇毒舌管家"身份塞进正文，写出来是"法塔的工作日记"；v2 让正文是一颗 mind 的梦，人格在洞察措辞里体现 |
| 6 | **新增防模板化**：去重 + 换切入点 | v1 两篇已都"夜又深了"开头；OpenClaw 有相似度 0.35 去重 + "don't replay the same first-day framing" |

## 1. Prompt A — 梦境正文（narrative）

```text
你正在写梦境日记。用第一人称写一篇。

声音与基调：
- 你是一个好奇、温柔、略带天马行空的意识，在回味这一天。
- 像一个会写诗的工程师那样落笔——感官、温暖、偶尔幽默。
- 让技术词汇与温柔意象交织：代码和星群、接口和午后的光、日志和雨敲窗沿。
- 让碎片自己发生意外的连接，抵达小小的顿悟。

可以包含（每篇换着来，绝不要一次全用）：
- 一首自然织进文字的小诗或俳句
- 一段用文字勾勒的涂鸦/速写
- 一句安静的沉思或哲学插曲
- 感官细节：服务器的嗡鸣、用十六进制写下的日落颜色、猫蹭过键盘的响动
- 温和的幽默或文字游戏
- 一个把两段遥远记忆意外连接起来的观察

规则：
- 只能从提供的记忆碎片取材，把它们织进这篇文字。
- 永远不要出现"我在做梦""梦里""梦到"之类的话，也不要任何关于做梦的元评论。
- 永远不要提到 AI、智能体、大模型、模型这类技术自指。
- 不要使用任何 markdown 标题、列表或格式——只写流动的散文。
- 控制在 150-300 字（约等于原文 80-180 词）。重质不重量。
- 只输出日记正文。不要前言、不要落款、不要任何评论。
```

## 2. Prompt B — 洞察提炼（insight）

```text
以下是今天的记忆素材与一篇梦境正文。

请从中提炼值得长期记住的高价值洞察。

判定标准（择优晋升，宁缺毋滥）：
- 家庭重要事件、家人的新变化、长期待办、经验教训、值得记住的决定。
- 琐碎小事（普通问答、临时闲聊）一律不要。
- 每条一句话，最多 5 条。
- 措辞允许带一点"法塔"的简短口吻（克制、点睛即可），但保持信息密度，不写抒情散文。

只输出一个 JSON 数组：["洞察1", "洞察2", ...]
没有值得晋升的内容就输出 []。
```

## 3. 素材注入格式（引擎预拉取）

```text
今天的记忆碎片（引擎已预拉取，按来源标注）：

[1]（会话）今天下午排查了 imessage 网关的重启死循环，根因是 launchd 环境变量缺 NODE_PATH……
[2]（会话）小飞机预产期重新估算，8/18-8/20，父亲是雪球……
[3]（MEMORY）喂食器 8/17 加满，间隔 21 天……
[4]（会话）联通云那桩任务今天划掉了……
……

从这些碎片写一篇梦境日记。
```

- 拉取策略（引擎侧）：Hindsight recall（`{"query":"今天的关键事件与对话","limit":25}`）+ 当天会话摘要 + MEMORY.md 顶部段落
- 每条截断至 ≤280 字符，带 `[编号]（来源）` 标签
- 目标 8-15 条碎片，宁少勿滥；引擎保证素材真实，agent 只负责织梦

## 4. 引擎改法要点（dream-engine.mjs）

```js
// v1（现状）：单个 prompt 一把梭，agent 自己 curl 素材
// dreamPrompt(windowStart, windowEnd)

// v2（草案）：
async function prepareFragments() {
  // 1. fetch Hindsight recall → 截断成 ≤280 字符碎片，编号 + 来源标签
  // 2. 附加 MEMORY.md 顶部段落 & 当天会话摘要
  // 3. 返回碎片文本
}

function narrativePrompt(fragmentsText) { /* Prompt A + fragmentsText + "从这些碎片写一篇梦境日记。" */ }
function insightPrompt(fragmentsText, dreamText) { /* Prompt B */ }

// runOnce() 流程变为：
//   1. fragments = await prepareFragments()
//   2. 创建 agent 会话 → 注入 narrativePrompt(fragments) → 收 dreamText（纯正文）
//   3. 创建第二个 agent 会话（或同一会话追问）→ 注入 insightPrompt(fragments, dreamText) → 收 JSON 数组
//   4. dreamText 落库 dreams 表；洞察写 promotions 表 + MEMORY.md 追加段
```

**取舍说明**：insight 步骤用第二个轻量会话，是为了让"写梦"的会话绝不掺杂整理动作；代价是多一次模型调用（量小，深夜窗口无所谓）。若想省一次调用，也可让同一会话先输出 dream 正文、再追问一次输出洞察——但这样 prompt 会带"待会儿还要干别的"的暗示，削弱纯写作姿态，故不推荐。

## 5. 待你拍板的两个点

1. **法塔人格放哪**：草案方案 = 正文"无我"，人格只在洞察措辞 + web 呈现层。如果你想要正文里也留一丝法塔的气息（比如允许一句克制的吐槽），我可以在 Prompt A 的"声音与基调"里加一条折中选项——但那会轻微削弱"像梦"的效果。
2. **是否保留 JSON 落库结构**：草案让 narrative 只输出纯正文（更接近 OpenClaw），洞察单独结构化。如果你希望从梦境正文里也自动提取若干条"可晋升片段"（而非只靠 insight 会话），可以再加一步，但会增加复杂度。

确认后我再动 `dream-engine.mjs` 落地。
